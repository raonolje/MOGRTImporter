## 기능 상태

모든 기능·상황에 결함이 없다는 판정은 하지 않는다. 기존 실제 Premiere 검증과
Codex 모델의 조회·제안·패널 승인·배치·완료 조회는 통과했다.
Claude Desktop의 패널 통신과 Claude Code 조직 인증 문제는 아직 미완료다.
세부 범위는 [MCP_VALIDATION.md](MCP_VALIDATION.md)를 따른다.

최종 보완 후 D드라이브에서 기본 검사 654개 중 644개 통과·10개 건너뜀,
별도 운영 캐시 검사 12개 통과, MCP 검사 14개 통과, ES3 위반 0건을 확인했다.
중복 2개를 제외한 고유 자동 검사는 668개다.

이번 코드 검토에서는 다음 두 문제를 보완했다. 이는 실앱 재검증과 구분되는
시뮬레이터/로더 회귀 검사로 확인한다.

1. **클립 삭제 실패의 결과 누락**: 적용 계획 뒤 삭제 대상 트랙이 잠기면 호스트는
   `locked`를 반환하지만 패널 작업은 `succeeded`가 될 수 있었다. `removeFailed`를
   최종 결과에 포함하고, 화면 오류와 `failed / apply-incomplete` 상태에 반영한다.
   잠금 해제 후 재시도 성공까지 회귀 검사한다.
2. **MCP 코어 해시와 실행 본문의 불일치 가능성**: 설치 파일을 해시 계산과 VM 실행에서
   각각 읽어 그 사이 파일이 교체되면 서로 다른 본문을 사용할 수 있었다.
   동일한 소스 스냅샷으로 해시와 실행 결과를 만든다. 설치 중 경합에 대한 보완이며,
   실제 사용자 타임라인 손상이 관찰됐다는 의미는 아니다.

## 반복문 선택 기준

`acc`는 별도의 문법이 아니라 `reduce`에서 흔히 사용하는 누산기 변수명이다.

| 작업 | 적합한 형태 |
|---|---|
| 각 항목을 새 값으로 변환 | `map` |
| 조건에 맞는 항목만 선택 | `filter` |
| 합계·통계 등 한 결과로 집계 | `reduce` 또는 읽기 쉬운 `for` |
| 첫 항목/존재 여부 찾기 | `find` / `some` |
| 순차 `await`, 중단·취소·부분 실패 처리 | `for` / `for...of` / `while` |
| 이전 계산에 의존하는 DP, 역순 제자리 삭제 | 기존 반복문 유지 |
| `hostscript.jsx` | ES3 호환 `for` 유지. `map/filter/reduce/for...of` 도입 금지 |

예를 들어 `mergeInputs`의 순수 배열 생성은 `filter/map` 후보이고,
`updateMultiSelect`의 통계는 순수 집계 함수로 추출할 수 있다.
Premiere 적용 루프를 `map(async ...)`로 바꾸면 반환된 Promise와 실행 순서를
별도로 관리해야 하므로 단순한 문법 치환으로 취급하면 안 된다.

`filter().map()`은 중간 배열과 추가 순회를 만들 수 있다. 짧아진 코드가 자동으로
빠른 코드는 아니므로 가독성·호환성·순서 보존을 먼저 판단한다.
배열 메서드의 반환값과 반복 규칙은 [ECMAScript 명세](https://tc39.es/ecma262/multipage/indexed-collections.html)를 참고한다.
